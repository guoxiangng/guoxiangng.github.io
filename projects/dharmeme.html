Why build it

Any general meme generator can do this if you type "make it Buddhist" into the prompt. So the value here is not capability, it is curation: a prompt tuned for one kind of joke, a hand-picked set of templates, and a bank of memes that a person has actually read and approved.

It is also a small, complete exercise in the question every free AI app has to answer: what stops a popular free thing from running up an unbounded model bill?

Two features

One costs nothing. One is metered.

Random

Tap, get a meme

Captions are written in batches, one template at a time, then reviewed by hand. Only approved ones are in the pool. The page loads the pool once and the button picks from it in your browser, so there is no model call and no cost per tap.

approved pool → canvas
Prompt

Give it a topic

One model call reads your topic and the template catalog, picks the template whose joke format fits, and writes the text for each of its slots. It returns a few short strings, and your browser does the drawing.

topic → {template_id, slots} → canvas
No magic

How the caption matches the picture

A meme template is a joke format with a fixed meaning, not just a picture. So a caption is always written for one specific template, never paired with an image at random. Each template is described in words the model can choose from.

catalog.yaml — one template

- id: drake
  format: >-
    Two panels. Top: something rejected
    with disgust. Bottom: the thing
    preferred instead.
  slots:
    - name: rejected
      box: [0.52, 0.02, 0.46, 0.46]
      max_chars: 70
    - name: preferred
      box: [0.52, 0.52, 0.46, 0.46]
      max_chars: 70

what the model returns

{
  "template_id": "drake",
  "slots": {
    "rejected":  "Letting go of attachment",
    "preferred": "Letting go of the 9am standup"
  }
}

validated before it is drawn:
  template exists · slot names match
  each text within max_chars
  one retry, then a random meme instead
Design decisions

Why it's built this way

No generated images

The model only ever writes text. Generating an image costs roughly a hundred times more than generating a caption, and a familiar template is funnier anyway because people already know the format.

Drawn in the browser

The meme is rendered on a canvas on your device. The backend returns a template name and a few strings, so it needs no image library and stays a tiny function. Text is wrapped, shrunk, and as a last resort truncated, so it never leaves its box.

A ceiling on the bill

The prompt feature has a per-visitor daily limit and a global daily cap, both counted before the model is called. Once the cap is reached the page says the meme well is empty for today and serves a random one. Cloud budget alerts only warn; the cap in the code is what actually stops spending.

It never looks broken

Every failure path, whether a declined topic, the limit, a bad model reply or an outage, ends the same way: a short message and a random meme from the approved bank.

Affectionate, not mocking

The jokes are about the practitioner's struggle: craving, distraction, forced calm. The prompt rules out ridiculing the Buddha, the Sangha, sacred objects or any other religion, and the model may decline a topic outright.

Architecture

A static page and one small function

Random   browser ─► the approved pool (fetched once per visit, no model call) ─► canvas
Prompt   browser ─► Lambda Function URL ─► usage check ─► Claude Haiku on Bedrock
                         └─► {template_id, slots} ─► canvas

site     GitHub Pages, built by a workflow from the repo
pool     DynamoDB — the live list of memes; the repo only holds a seed
limits   DynamoDB counters — per visitor per day, and one global per day
brain    Claude Haiku on Amazon Bedrock, behind a provider interface
deploy   AWS SAM · one zip Lambda · ap-southeast-1
