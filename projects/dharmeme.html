What it does

Four things

Random

A pool a person has read

Random deals from a pool of memes that were each approved by hand. No model runs when you tap it, so it is instant and costs nothing.

approved pool → drawn on your device
Themes

A fresh one, on a Buddhist theme

Pick a theme, from impermanence to Pure Land practice, and a model chooses a template and writes the caption. There is no text box: visitors pick, they never type.

theme → {template, text} → drawn

A separate set of themes and a separate prompt for 汉传佛教 and 人间佛教: 念佛, 吃素, 随缘, 做义工. Available in Simplified and Traditional characters.

Feedback

Thumbs that can't snowball

Every pool meme has 👍, 👎 and Report. Votes nudge the order but never the exposure: each meme is shown once before any repeats, so popular ones don't crowd out the rest.

votes → order, not frequency
Design decisions

Why it's built this way

Curation, not capability

Any general meme tool can do this if you type "make it Buddhist". The value here is what a general tool lacks: a tuned voice, hand-placed templates, and a pool a person has actually read.

Visitors pick, they don't type

The first version had an open topic box. People test those, and a religious project is a poor place to find out what they type. It was replaced with a fixed list of themes, so nothing a stranger writes ever reaches the model. No content filter to maintain, because there is nothing to filter.

A person approves, a model proposes

A daily job writes new memes and a second model call reviews them against the tone rules. The survivors still wait as pending until the owner approves each one in a private chat. The pool only grows through a human decision.

Even exposure

Ranking by popularity feeds itself: whatever is shown most gets the most votes. Here every meme appears once per pass, votes only shift the order, a rating counts by rate and not by volume, and nothing counts until ten votes. 500 thumbs up earn no more than 10 at the same rate.

A ceiling on the bill

A free app that calls a model on every tap has no cost ceiling. Random calls no model at all. Themed memes are capped per visitor and per day, counted before the model is called. The daily job makes a fixed number of calls whatever the traffic. Cloud budget alerts only warn; the cap in the code is what stops spending.

It never looks broken

Limit reached, model error, service down: every failure ends the same way, a short on-theme message and a meme from the pool. The website keeps a bundled copy of the pool and works with the backend off.

Affectionate, not mocking

The jokes are about craving, distraction and forced calm. The prompt rules out ridiculing the Buddha, the Sangha, sacred objects or any other religion; for Pure Land practice the joke is on the practitioner's wandering mind, never on Amitabha. A reported meme goes to the owner to keep or remove.

How the caption matches the picture

A meme template is a joke format with a fixed meaning, not just a picture. Each one is described in words, with its text boxes as fractions of the image. The model is offered a random four of the thirty, so it can't lean on one favourite, and returns only a template name and a few strings.

catalog.yaml — one template

- id: bike-fall
  format: >-
    A cyclist pushes a stick into his
    own wheel, crashes, and blames
    something else.
  slots:
    - name: self_sabotage
      box: [0.07, 0.50, 0.36, 0.15]
      max_chars: 35
    - name: blame
      box: [0.46, 0.71, 0.47, 0.12]
      max_chars: 35

what the model returns

{
  "template_id": "bike-fall",
  "slots": {
    "cyclist": "Me",
    "self_sabotage": "Checking my phone before bed",
    "blame": "Why is my mind so restless"
  }
}

checked before it is drawn:
  template exists · slot names match
  each text within its limit
  if not, one retry that says what was wrong
  then a meme from the pool instead

The daily batch

How the pool grows without anyone writing captions, and without anything going out unread.

  1. Write. One model call writes a meme for each of the templates that have the fewest, shown what the pool already has so it doesn't repeat itself.
  2. Check. Plain code drops anything invalid, over length, or a duplicate.
  3. Review. A second, separate model call passes or fails each one against the tone rules. If its verdict can't be read, nothing is added.
  4. Hold. Survivors are stored as pending and are invisible everywhere.
  5. Approve. Each is sent to the owner's chat with Approve and Reject. Only presses from that one chat count, and a meme is never sent twice.

Drawing the text

Text is wrapped to its box, then the font shrinks until it fits with every word whole; a word is split or text truncated only at the minimum size, so nothing leaves its box. The browser draws on a canvas, and a Python twin of the same rules draws for Telegram, which needs a real image file. Chinese has no spaces, so it breaks between characters, never starts a line with a comma or full stop, and uses a Chinese font, since the classic meme typeface has no Chinese glyphs.

One Chinese source, two scripts

Chinese themes, the prompt and every caption are written and stored once, in Traditional characters. The Simplified version is that text converted character by character, so the two can't drift apart and each caption is vetted once.

Tests and deployment

106 automated tests (92 Python, 14 JavaScript) cover the text fitting, the model's reply handling with a stubbed model, the limits, the votes, the bot, the generator and the Chinese rendering. Every push runs them; the site then builds and deploys by itself, and the build fails if a template image is missing or not the size its text boxes were placed on. The API is defined in one AWS SAM template.
