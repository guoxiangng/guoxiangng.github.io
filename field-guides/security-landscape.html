1 · Core ideas

CIA triad

Confidentiality (only the right people see it), Integrity (it isn't tampered with), Availability (it works when needed). Every control protects at least one. Ransomware hits A and often C.

Asset, threat, vulnerability, risk

Asset: what you protect. Threat: who or what could harm it. Vulnerability: the weakness. Exploit: how the weakness is used. Risk ≈ likelihood × impact.

AAA

Authentication (who are you), Authorization (what may you do), Accounting (what did you do: logs). Most cloud breaches are an AAA failure.

Least privilege

Grant only what a task needs, for only as long as it's needed (just-in-time access). Limits blast radius when, not if, something is compromised.

Defence in depth

Layers of independent controls so one failure isn't a breach. Section 2 is built on this idea.

Zero trust

No implicit trust from network location. Verify identity, device and context on every request (NIST SP 800-207). Workload identity (SPIFFE) with default-deny policies is zero trust applied to services and AI agents.

Prevent, detect, respond

Prevention always fails eventually, so you also need detection (to know) and response (to limit damage). An MDR team lives in detect and respond.

Assume breach

Design and monitor as if an attacker is already inside. Drives segmentation, logging and rehearsed incident response.

8 · An attack, step by step (MITRE ATT&CK tactics)

A realistic cloud intrusion walked through the 14 ATT&CK tactics. Practise telling this story with "what would fire, and what I'd do".

#TacticIn this storyWhat could catch itYour response
1–2Recon / Resource developmentAttacker scans for exposed services; sets up a C2 server and mining pool accountMostly invisible to you; threat intel later—
3Initial AccessExploits an unpatched internet-facing web app running in a podWAF logs; a runtime-aware vulnerability tool would have ranked this CVE first (exposed + loaded)Confirm exploit path from logs
4ExecutionWeb server process spawns sh and runs curl | shRuntime sensor: shell spawned by web server, download-and-executeTriage: is this normal for the app? (usually not)
5PersistenceCreates a CronJob / new IAM user with access keyK8s audit log; CloudTrail CreateUser, CreateAccessKeyInventory everything created after initial access
6Privilege EscalationPod is privileged; mounts host filesystemRuntime (container escape indicators); CSPM had flagged the privileged podTreat the node as compromised
7Defense EvasionDeletes shell history; tries to stop CloudTrailRuntime (log tampering); CloudTrail StopLogging alertEscalate severity; check org-level trail is intact
8Credential AccessReads SA token; queries IMDS for the node roleRuntime (token read, IMDS access); GuardDuty if the credentials are used from outsideRevoke sessions, rotate, block IMDS from pods
9DiscoveryLists S3 buckets, IAM roles, secretsCloudTrail burst of List*/Describe* from a new principalScope what the stolen role could reach
10Lateral MovementAssumes a more privileged role; reaches other podsCloudTrail AssumeRole chain; NetworkPolicy/mesh deniesContain: deny policies on the roles, isolate pods/nodes
11CollectionCopies customer data into staging bucketMacie/DSPM; S3 data eventsIdentify exactly which data (needed for PDPA notification)
12Command & ControlOutbound beacon to attacker serverRuntime network events, DNS logs, GuardDuty threat intelBlock egress; collect IOCs
13ExfiltrationUploads archive to external storageUnusual egress volume, flow logsStop transfer, preserve evidence
14ImpactLaunches miners on GPU instances; deletes backupsCost anomaly, GuardDuty crypto findings, Backup eventsEradicate, recover from immutable backups, post-incident review
Investigation habit: for any alert, work through three things: what evidence you'd pull (runtime events, CloudTrail, K8s audit, flow logs), how you'd scope it (which identity, what it could reach), and how you'd contain without destroying evidence (snapshot before terminate, deny policy before delete).

9 · How a SOC / MDR team works

Detection engineering

Writing, testing and tuning detection rules as code: version control, test data, false-positive budgets, ATT&CK coverage maps.

Threat hunting

Proactively searching for attackers that didn't trigger alerts, starting from a hypothesis ("is anyone using IMDS from pods?").

Playbook

Per scenario: trigger, questions to answer, evidence to collect, containment options, communication, closure criteria.

Metrics

MTTD (time to detect), MTTR (time to respond/remediate), false-positive rate, coverage of ATT&CK techniques.

Red / blue / purple

Red attacks, blue defends, purple is both together to test and improve detections.

Breach & attack simulation (BAS)

Tools that safely replay attacker techniques to check detections fire (e.g. Atomic Red Team, Falco event-generator, GuardDuty tester).

10 · Prioritising vulnerabilities

Every environment has thousands of CVEs. The skill is choosing the few that matter.

SignalWhat it tells youLimitation
CVSSSeverity of the flaw in general (0–10)Says nothing about your environment or whether anyone exploits it
EPSSProbability of exploitation in the next 30 daysStill not about your environment
CISA KEVKnown to be exploited in the wildShort list; absence doesn't mean safe
SSVCDecision tree: act / attend / trackNeeds your context as input
Exposure (internet-facing?)Can an attacker reach it?Needs network and graph analysis
Runtime reachability (in use?)Is the vulnerable package actually loaded or executed?Needs a runtime sensor (the pitch of runtime-first CNAPPs)
Blast radiusWhat the workload's identity can reach (data, admin roles)Needs CIEM
A good prioritisation combines them: "Critical CVSS, on KEV, in a package that's loaded, on an internet-facing pod whose role can read customer data" is a fix-today. The same CVE in an unused library in an internal batch job can wait.

11 · Glossary of terms not covered on the companion page

Identity

  • IdP / SSO: one login across apps
  • SAML / OIDC / OAuth 2.0: federation protocols (OAuth is authorisation; OIDC adds identity on top)
  • MFA / phishing-resistant MFA: FIDO2/passkeys beat SMS and push
  • PAM: privileged access management (vaulting, session recording)
  • IGA: identity governance (joiner-mover-leaver, access reviews)
  • JIT access: temporary elevation instead of standing admin

Network

  • NGFW: firewall with app awareness and IPS
  • IDS / IPS: detect / block network attacks
  • SASE / SSE: network + security delivered from the cloud
  • ZTNA: per-app access replacing VPN
  • SWG / CASB: web filtering / SaaS usage control
  • NDR: detection from network traffic

Endpoint & workload

  • EPP: prevention (antivirus successor)
  • EDR: endpoint detection and response
  • MDM: device management
  • FIM: file integrity monitoring (e.g. Tripwire)
  • Hardening: CIS benchmarks, minimal images

Data

  • DLP: stop sensitive data leaving
  • Encryption at rest / in transit: KMS, TLS
  • KMS / HSM: key management / hardware key storage
  • Tokenisation: replace data with a reference
  • Immutable backups: can't be deleted by an attacker (vault lock)

SecOps

  • UEBA: behaviour baselines for users/entities
  • TI / CTI: threat intelligence
  • Triage: decide if an alert is real and how urgent
  • Containment: limit spread without destroying evidence
  • Forensics: preserve and analyse evidence (snapshots, memory)
  • Chain of custody: evidence handling record

Testing & GRC

  • Pentest / red team: scoped test / full adversary simulation
  • Bug bounty: paid external researchers
  • Policy / standard / procedure: why / what / how
  • Control: a safeguard that reduces risk
  • Risk register: tracked risks with owners
  • Attestation: audited evidence (SOC 2 report)
